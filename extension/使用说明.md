# 文章打包 — 使用说明

**把任何网站上的长文**，剥掉广告导航只留正文，一键打包成**图文 Markdown**（存 Obsidian）
或**单文件 HTML**（图片全内嵌）。

两条提取路线，按网站自动分流：

| 网站 | 走哪条 |
|---|---|
| x.com / twitter.com | **X 专用逻辑**（认得 DraftJS 结构、引用推文、代码块） |
| 其它任何网站 | **通用提取**（Readability，和浏览器"阅读模式"同一套算法） |

---

## 安装

1. 浏览器打开 `chrome://extensions`（Brave 是 `brave://extensions`）
2. 打开右上角 **开发者模式**
3. 点 **加载已解压的扩展程序**
4. 选中本仓库里的 **`extension/`** 文件夹
5. 工具栏出现米白底的口袋图标（点拼图图标可以把它固定住）

> ⚠️ 解压后的文件夹**不能删、不能挪**，删了插件就没了。

---

## 用法

1. 打开任意一篇文章（X 长文、新闻、博客、维基…都行）
2. 点插件图标 → **提取本页文章**
3. 弹窗里核对一下**标题**和**图片张数**，确认抓对了
4. 选一种保存方式：
   - **下载 Markdown + 图片** —— 存进 Obsidian 用这个。会建一个以标题命名的文件夹，
     里面是 `.md` 加所有图片，md 里的图片链接已经改成本地相对路径
   - **下载 HTML** —— 存档、发给别人用这个。**一个文件，图片全内嵌在里面**：
     断网能看、换设备能看、发给别人也能看，不依赖原网站。
     用任何浏览器双击就打开，手机上也行。

> **下载在后台跑，弹窗可以随手关掉。**
> 关掉再打开，提取结果还在，按钮还能接着点 —— 不用重新提取。

## 常见问题

**Q：点了提示「页面没有响应」？**
A：刷新一下页面再试。（插件会自动注入脚本，正常情况下不需要手动刷新。）

**Q：卡片上出现「⚠️ 正文里一半以上的字都在链接里」？**
A：说明你可能在**首页或列表页**上点了提取，抓到的是一堆标题链接而不是文章。
点进具体那篇文章再试。（这只是提醒，不拦着你——判断偶尔会错。）

**Q：有的网站抓不出来？**
A：通用提取靠的是启发式算法，不是万能的。特别难搞的是：
需要登录才显示正文的、正文全靠 JS 异步加载的、把内容藏在 iframe 里的。
遇到抓不好的站，欢迎提 issue，如果值得就为它写专用规则（像 X 那样）。

**Q：为什么点下载时会弹权限窗？**
A：图片可能在任意域名上，后台去抓图需要那个域名的权限。
插件只申请**当前这篇文章图片所在的域名**，不会一次性要"所有网站"。
不给也行，正文照样能存，只是图片下不来。

**Q：提取到的正文不全 / 混进了不该有的内容？**
A：提个 issue 附上文章链接。X 的 DOM 结构时常变动，专用规则需要跟着调。

**Q：图片下载失败几张？**
A：弹窗状态里会写明失败了几张、什么原因。多半是网络超时，重试一次通常就好。

**Q：HTML 文件为什么这么大？**
A：因为图片是**编码后写进文件里**的，不是外部引用。这种编码方式体积会膨胀约三分之一。
一篇 10 张图的文章大概 5～8 MB。代价换来的是「一个文件走天下」。

**Q：以前那个「导出 DOCX」按钮呢？**
A：**撤掉了，但功能还在。** 那条路（导进在线文档再转发）已经不走了，所以从界面上移除。
代码完整保留在 `background.js` 的 `doDocx()` 和 `docx.js` 里 ——
恢复方法写在 `background.js` 里 `doDocx()` 上方的注释块中。

**Q：为什么下载图片要那么久？**
A：两个原因，都是为了**不丢图**：

1. 不能让浏览器的下载管理器直接去拉图（在 Brave 里会卡死不结束），
   所以是插件后台自己把图抓成字节再交给下载器
2. **必须限速**。实测连续快速请求 28 张图，会有 21 张被图床限流（HTTP 429）。
   现在每张之间隔一下，遇到限流还会退避重试

28 张图大约要 80 秒。慢，但一张不丢。

## 两种输出

```
任何网页长文 ──提取──┬──→ Markdown + 图片 ──→ Obsidian / Logseq / 本地归档
                     └──→ 单文件 HTML（图片内嵌）──→ 存档 · 离线看 · 发给别人
```

「除了存在本地，还能不能一键送到别处」这件事仍在讨论中。
